# First-visit usability release

Base: f7f35adb695c0158b51ca23e3704b7cc2afc6564, including requested baseline 58361bd94a6700a0523f6de8bf664c3fdc21c5dc and later accepted PR #124.

The source review covered the homepage, shared layout, history overview, chapter catalogue, Browse Svelte component, timeline, network implementation, publications and PDF reader, Pagefind search and responsive stylesheet. The first-visit barriers were a chapter-first primary action, 44 duplicate homepage chapter cards, a 28-story random pool, very long per-dataset navigation, and inaccurate author/filter and local PDF labels.

The short history is now the primary route, with a practical GIS definition, reading-time guidance and explicit onward choices. Five existing documented stories form a scroll-snap slider with previous/next, keyboard arrows, swipe and optional timed playback. Playback stops on focus, pointer entry and page hiding; reduced motion removes smooth scrolling. The existing documentary background has a pause/play control. Six chapter previews lead into the full 44-chapter catalogue. A collapsed list retains every homepage chapter anchor. Theme previews retain imagery and limit lengthy descriptions.

Desktop and mobile have the same direct Short history, Chapters, Timeline, Publications, Search and Contribute destinations. Explore groups People & organisations, Connections, Themes, Datasets and About & sources. Native disclosures retain Escape, focus return, arrow keys and outside-click behaviour. Timeline starting links use existing event IDs; network examples use existing relationships with sources and retain graph controls, filtering and evidence. Search and chapter catalogue have first-visit entry guidance.

The publication creator filter is labelled Author / organisation to match its actual data. The embedded PDF fallback names the locally hosted PDF. Footer contribution wording is consistent. File totals are measured from the final build and link totals from the internal-link validator, then inserted into the generated homepage. Counts are link occurrences, rather than unique destinations; totals can change with navigation and generated assets.

No historical content collection files, chapter prose, publication records, source metadata, imagery records, deep-link identifiers or exclusions were changed. All timeline data remains limited to 31 December 2025. Publication archive routes and local PDF storage are unchanged.

Validation: npm ci, 157 passing automated tests, production build, content/media checks and preservation of 5,543 complete files. Chromium first-visit checks cover 1440, 1280, 768, 390 and 320 px: introduction, chapter selection, Pagefind search, timeline selection, graph evidence, decade and creator filters, local PDF response and contribution context. Axe checks WCAG A/AA on nine routes at each width. Grouped navigation keyboard checks and text contrast cover all five palettes in light/dark modes at six widths including 1024 px. Existing homepage/contribution and tile navigation checks remain in CI with updated redesign expectations. Browser evidence is retained in CI artifacts.

Limits: Chromium automation does not certify all assistive technology or native PDF viewers. The PDF checks establish a local reader object, a same-site URL and a successful response beginning with the PDF signature. They do not establish identical rendering inside every browser's PDF viewer. Contribution checks inspect prepared links and copy functions without sending email. Search-engine crawling checks establish discoverability, not search-engine submission or indexing.
